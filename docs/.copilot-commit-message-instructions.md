# Instrucciones para la generación de mensajes de commit

Genera siempre los mensajes de commit en español, siguiendo estas reglas:

## 1. Usa el formato Conventional Commits

Tipos permitidos:

- **feat:** nueva funcionalidad
- **fix:** corrección de errores
- **docs:** cambios en documentación
- **refactor:** refactorización sin alterar comportamiento
- **test:** cambios o adición de pruebas
- **chore:** tareas de mantenimiento
- **perf:** mejoras de rendimiento
- **build:** cambios en dependencias, CI/CD o build system

## 2. Estilo del mensaje

- El mensaje debe estar escrito en **modo imperativo**:
  - “agregar”, “corregir”, “actualizar”, “eliminar”.
- Título breve (ideal: < 70 caracteres).
- Si es necesario, agrega descripción en párrafo adicional:
  - qué se cambió
  - por qué
  - impacto
  - contexto técnico relevante

## 3. Reglas adicionales

- Sé claro, conciso y específico.
- Resume los cambios más relevantes.
- Si hay cambios en modelos de IA, datos o pipelines, explícalos de forma explícita.
- Evita frases vagas como: “varios cambios” o “arreglos menores”.
